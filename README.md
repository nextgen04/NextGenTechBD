# 🛍️ NextGenTechBD — Cloudflare Pages + D1 ব্যাকএন্ড সহ ই-কমার্স সাইট

ডারাজ-স্টাইল ই-কমার্স ফ্রন্টএন্ড, যা **Cloudflare Pages**-এ হোস্ট হয় এবং **Cloudflare Pages Functions + D1 SQL ডেটাবেজ** দিয়ে বানানো নিজস্ব ব্যাকএন্ড API ব্যবহার করে। পণ্য, ক্যাটাগরি, সেটিংস ও অর্ডার — সবকিছু D1 ডেটাবেজে সংরক্ষিত থাকে, এবং একটা কাস্টম অ্যাডমিন প্যানেল থেকে ম্যানেজ করা যায়।

> ## 🚀 পাবলিশ করতে চান?
> **[DEPLOY-GUIDE.md](DEPLOY-GUIDE.md)** ফাইলটি দেখুন — GitHub + Cloudflare Pages + D1 দিয়ে ধাপে ধাপে বাংলা গাইড।

## 🏪 মাল্টি-সেলার মার্কেটপ্লেস (Daraz-স্টাইল)

এই সাইট এখন একটি **মাল্টি-সেলার মার্কেটপ্লেস**: একাধিক সেলার নিজের নিজের পণ্য, স্টক ও অর্ডার ম্যানেজ করে; গ্রাহক এক কার্টে একাধিক সেলারের পণ্য কিনতে পারে; আর পুরো মার্কেটপ্লেসের উপর **Super Admin**-এর পূর্ণ নিয়ন্ত্রণ থাকে। আগের সব ফিচার (গ্রাহক লগইন, অর্ডার ট্র্যাকিং, কুপন, রিভিউ, Cloudinary আপলোড, অ্যাডমিন প্যানেল) আগের মতোই চলে — আগের সব পণ্য "NextGenTechBD Official" নামের ডিফল্ট সেলারের অধীনে চলে যায়।

| ভূমিকা | কোথায় ঢোকে | কী করতে পারে |
|---|---|---|
| **Super Admin** | `/admin/` | সেলার তৈরি/সাসপেন্ড/ব্লক/ডিলিট/পাসওয়ার্ড রিসেট, ট্রায়াল ও সাবস্ক্রিপশন নিয়ন্ত্রণ, সব সেলারের পণ্য-অর্ডার-বিক্রি দেখা ও বদলানো, পণ্য ট্রান্সফার, ক্যাটাগরি/কুপন/ব্যানার/সেটিংস/রিভিউ মডারেশন |
| **Seller** | `/seller/login` → `/seller/` | শুধু **নিজের** পণ্য/স্টক/অর্ডার/রিভিউ/প্রোফাইল ও বিক্রির হিসাব। অন্য সেলারের কিছুই দেখতে বা বদলাতে পারে না |
| **Customer** | `/` | সব সেলারের পণ্য দেখা, সেলার অনুযায়ী ফিল্টার, `/store/<স্টোর>` পেজ, কেনা, অর্ডার ট্র্যাক |

### 🔑 Super Admin লগইন ফ্লো
1. `https://আপনার-সাইট.pages.dev/admin/` খুলে **ADMIN_KEY** দিয়ে লগইন করুন (Cloudflare Pages → Settings → Environment variables-এ সেট করা)।
2. লগইন সফল হলে সার্ভার একটি **HttpOnly, SameSite=Strict** কুকি-সেশন (১২ ঘণ্টা) দেয় — কী আর ব্রাউজারে জমা থাকে না। পুরনো `X-Admin-Key` হেডারও আগের মতো কাজ করে।
3. ভুল কী ১০ বার দিলে ওই আইপি ১৫ মিনিটের জন্য আটকে যায়; প্রতিটি চেষ্টা **🔐 সিকিউরিটি** ট্যাবের লগে থাকে। `ADMIN_KEY` বদলালে পুরনো সব সেশন নিজে থেকেই বাতিল হয়।
4. সেলার কখনো অ্যাডমিন API খুলতে পারে না — সেলার ও অ্যাডমিনের কুকি, টেবিল ও রোল সম্পূর্ণ আলাদা।

### 🏪 সেলার তৈরি করা (Super Admin)
**অ্যাডমিন → 🏪 সেলার → নতুন সেলার।** দিতে হয়: নাম, স্টোরের নাম, **ইউজারনেম/সেলার আইডি** (ইউনিক, বড়-ছোট হাতের অক্ষর গণ্য হয় না), পাসওয়ার্ড (কমপক্ষে ৮ অক্ষর, অক্ষর + সংখ্যা), মোবাইল, ইমেইল, ঠিকানা, লোগো (https লিংক), বিবরণ, স্ট্যাটাস।
- পাসওয়ার্ড কখনো সরল টেক্সটে সেভ হয় না (PBKDF2 + আলাদা salt)। ফাঁকা রাখলে সিস্টেম নিজেই একটা শক্ত পাসওয়ার্ড বানিয়ে **একবার** দেখায়।
- সেলারের স্টোর লিংক নিজে থেকে তৈরি হয় (`/store/abc-electronics`)।
- তৈরি হওয়ার মুহূর্তেই **১৫ দিনের ফ্রি ট্রায়াল** শুরু হয়।
- **অ্যাকশন:** দেখুন (পণ্য, অর্ডার, বিক্রির সারাংশ, স্টক, সাবস্ক্রিপশন ইতিহাস, লগইন লগ) · এডিট · পাসওয়ার্ড রিসেট (পুরনো সব সেশন বাতিল) · Suspend / Active / Block (চলমান সেশনও সাথে সাথে বন্ধ) · ডিলিট (আসলে নিষ্ক্রিয় — পণ্য ও অর্ডারের ইতিহাস থাকে)।
- ডিফল্ট সিস্টেম সেলার "NextGenTechBD Official" সাসপেন্ড/ডিলিট/রিসেট করা যায় না এবং তাতে লগইন করা যায় না।

### 🔐 সেলার লগইন ও সিকিউরিটি
- `/seller/login`-এ ইউজারনেম + পাসওয়ার্ড। সফল হলে **SELLER_SESSION** কুকি (HttpOnly, SameSite=Strict, HTTPS-এ Secure, ৭ দিন)। সেশন টোকেন ডেটাবেজে কাঁচা থাকে না, শুধু SHA-256 হ্যাশ।
- একই ইউজারনেমে ৫ বার ভুল পাসওয়ার্ড বা একই আইপি থেকে ২০ বার ভুল হলে ১৫ মিনিট লক; ইউজারনেম আছে কি নেই — বার্তা ও সময় একই (আন্দাজ করা যায় না)। প্রতিটি লগইন-চেষ্টা `seller_login_log`-এ।
- Suspend/Block/Delete করলে সেলারের চলমান সেশনও তৎক্ষণাৎ অকার্যকর। পাসওয়ার্ড বদলালে বাকি সব সেশন বাতিল।
- **সেলারের পরিচয় সবসময় সার্ভারের সেশন থেকে আসে** (`getAuthenticatedSeller`) — ব্রাউজার থেকে পাঠানো `seller_id` কখনো বিশ্বাস করা হয় না। প্রতিটি কুয়েরিতে `WHERE id = ? AND seller_id = ?`; অন্যের জিনিস চাইলে **404** (অস্তিত্বই বোঝা যায় না → IDOR নেই)।
- রোল/পারমিশন: `SUPER_ADMIN`, `SELLER`, এবং ভবিষ্যতের জন্য প্রস্তুত `SELLER_STAFF` (`functions/_lib/auth.js` → `ROLE_PERMISSIONS`)।

### 📊 সেলার ড্যাশবোর্ড (`/seller/`)
মোবাইল-ফ্রেন্ডলি। ট্যাব: **ড্যাশবোর্ড** (মোট/সক্রিয়/লো-স্টক পণ্য, মোট/পেন্ডিং/সম্পন্ন অর্ডার, আজ/সপ্তাহ/মাস/মোট বিক্রি, নতুন-অর্ডার তালিকা, ট্রায়ালের বাকি দিন) · **পণ্য** · **অর্ডার** · **রিভিউ** · **প্রোফাইল** (স্টোরের তথ্য, লোগো, পাসওয়ার্ড বদল)।
- নতুন অর্ডার এলে 🔔 ব্যাজ + টোস্ট + হালকা শব্দ (৩০ সেকেন্ড পর পর চেক)।
- **পণ্য ম্যানেজমেন্ট:** যোগ/এডিট/ডিলিট, ছবি আপলোড (Cloudinary, `nextgentechbd/sellers/<id>` ফোল্ডারে), মূল্য, পুরনো মূল্য, স্টক (ইন/আউট + ইতিহাস), SKU, ক্যাটাগরি, বিবরণ, রং, সাইজ, ⚡ ফ্ল্যাশ সেল, ⭐ ফিচার্ড, স্ট্যাটাস (সক্রিয়/নিষ্ক্রিয়/ড্রাফট)।
- সেলার **নতুন ক্যাটাগরি বানাতে পারে না** — Super Admin-এর তৈরি ক্যাটাগরি থেকে বাছাই করে। সেলার `rating`, `sold` বা `seller_id` নিজে বসাতে পারে না।
- অর্ডারে থাকা পণ্য "ডিলিট" করলে মোছার বদলে নিষ্ক্রিয় (আর্কাইভ) হয়; অর্ডারবিহীন পণ্য মুছে যায়।
- অ্যাডমিন চাইলে পণ্য এক সেলার থেকে অন্যজনে **ট্রান্সফার** করতে পারে (অ্যাডমিন → পণ্যসমূহ → টিক দিয়ে বাছাই → ট্রান্সফার), অডিট লগসহ (`product_transfers`)। আগের অর্ডার আগের সেলারের কাছেই থাকে।

### 🛒 মাল্টি-সেলার কার্ট ও অর্ডার ফ্লো
1. গ্রাহক এক কার্টে একাধিক সেলারের পণ্য রাখতে পারে।
2. চেকআউটে ব্রাউজার শুধু `{পণ্যের id, সংখ্যা}` পাঠায়। **দাম, সেলার, ডেলিভারি ফি, কুপনের ছাড় ও স্টক সার্ভার নিজে হিসাব করে** — ব্রাউজারের পাঠানো দাম/মোট কখনো বিশ্বাস করা হয় না।
3. একটি `orders` সারিতে গ্রাহকের মূল অর্ডার; প্রতিটি পণ্য আলাদা `order_items` সারি (সেলার, নাম/দামের snapshot, `seller_status`)। স্টক শর্ত দিয়ে কাটা হয় (ঋণাত্মক হয় না); কার্টের কোনো পণ্য স্টকে না থাকলে কিছুই কাটে না।
4. সাসপেন্ড/ব্লক/মুছে-ফেলা/মেয়াদ-শেষ সেলারের পণ্য বা নিষ্ক্রিয় পণ্য কেনা যায় না। সেলার-নির্দিষ্ট কুপন শুধু ওই সেলারের অংশে লাগে।
5. **সেলার** শুধু নিজের আইটেম ও ফুলফিলমেন্টের জন্য লাগে এমন গ্রাহক-তথ্য (নাম, ফোন, ঠিকানা, জেলা, পেমেন্ট মাধ্যম, নোট) দেখে; স্ট্যাটাস বদলায়: Pending → Processing → Confirmed → Shipped → Delivered / Cancelled / Returned। বাতিল করলে স্টক ফেরত আসে।
6. **Super Admin** পুরো অর্ডার বা নির্দিষ্ট সেলারের পার্সেল override করতে পারে (অ্যাডমিন → অর্ডারসমূহ → সেলার-ভিত্তিক পার্সেল)।
7. গ্রাহকের দেখা মূল অর্ডারের অবস্থা সব সেলারের আইটেম থেকে নিজে হিসাব হয়; ট্র্যাকিংয়ে সেলার-ভিত্তিক পার্সেল (কুরিয়ার/ট্র্যাকিং আইডিসহ) দেখায়।
8. অপব্যবহার-রোধ: একই ফোনে ১০ মিনিটে ৫টির বেশি অর্ডার নয়; ডাবল-ক্লিকে একই `orderNo` + ফোনে নতুন অর্ডার/স্টক-কাটা হয় না। নেটওয়ার্ক-সমস্যায় আগের মতো হোয়াটসঅ্যাপ অর্ডার ব্যাকআপ চলে।
9. কমিশনের কলাম (`commission_percent`, `commission_amount`, `seller_earning`, `platform_earning`) প্রস্তুত; এখন কমিশন ০%।

### 🎁 ১৫ দিনের ফ্রি ট্রায়াল ও সাবস্ক্রিপশন (Super Admin নিয়ন্ত্রণ করে)
**অ্যাডমিন → 💳 সাবস্ক্রিপশন:** ট্রায়ালের দিন (ডিফল্ট ১৫), সাবস্ক্রিপশন বাধ্যতামূলক কি না, গ্রেস পিরিয়ড, মেয়াদ শেষে পণ্য লুকানো/দেখানো, এবং **প্ল্যান** (নাম, দাম, মেয়াদ, পণ্যসীমা) ঠিক করুন। প্রতিটি সেলারের জন্য: ট্রায়াল বাড়ানো · প্ল্যান চালু/নবায়ন (bKash/Nagad/ব্যাংক ইত্যাদির পেমেন্ট রেকর্ডসহ) · ম্যানুয়াল Allow/Deny override · এখনই মেয়াদ শেষ।
- অবস্থা: **trial** → **active** (পেইড) → **grace** → **expired**। মেয়াদ শেষে (ডিফল্ট) পণ্য দোকান থেকে লুকায়, নতুন পণ্য যোগ/এডিট/স্টক-বদল বন্ধ — কিন্তু সেলার লগইন করে চলমান অর্ডার সামলাতে ও পণ্য মুছতে পারে।
- সেলার ড্যাশবোর্ডে ট্রায়ালের বাকি দিন/মেয়াদ-শেষের ব্যানার দেখায়; অ্যাডমিন ড্যাশবোর্ডে "৭ দিনে শেষ হবে" ও "মেয়াদ-শেষ" গণনা।
- **পেমেন্ট গেটওয়ে নেই:** সেলার bKash/Nagad-এ টাকা দিলে Super Admin পেমেন্ট রেকর্ড করে সাবস্ক্রিপশন চালু করেন।

### 🌐 গ্রাহকের সামনে
- **হোমপেজ:** সব সক্রিয় সেলারের পণ্য একসাথে; কার্ডে "🏪 স্টোরের নাম" (ক্লিক করলে স্টোরে); **"বিক্রেতা অনুযায়ী কিনুন"** ফিল্টার; সার্চে স্টোরের নামও মেলে; ফিচার্ড পণ্য আগে।

- **স্টোর পেজ** `/store/<slug>`: লোগো, নাম, বিবরণ, রেটিং, পণ্য সংখ্যা, সার্চ/ক্যাটাগরি/সর্ট, পণ্য গ্রিড, সরাসরি কার্টে যোগ। (`public/_redirects`-এর `/store/* → /store/index.html` রিরাইট লাগে — Pages নিজে পড়ে নেয়।)

### 🛡️ সিকিউরিটি সারাংশ
Seller ID manipulation, IDOR, অন্যের পণ্য/অর্ডার/স্টক বদল, সেলার দিয়ে অ্যাডমিন API, পাসওয়ার্ড ফাঁস, SQL ইনজেকশন (সব কুয়েরি `bind`), XSS (গ্রাহক/সেলারের ডেটা সর্বত্র escape), CSRF (SameSite=Strict + Origin যাচাই), ক্লিকজ্যাকিং (অ্যাডমিন/সেলার পেজে `X-Frame-Options: DENY` + CSP) — সব **সার্ভার-সাইডে** আটকানো; ফ্রন্টএন্ড রুট লুকানো নিরাপত্তা হিসেবে ধরা হয়নি। `npm test` প্রতিবার সব `/api/admin/*` ও `/api/seller/*` এন্ডপয়েন্ট অনামী/গ্রাহক/ভুল-রোল দিয়ে পরীক্ষা করে এবং কেউ লগইন-ছাড়া নতুন এন্ডপয়েন্ট যোগ করলে ফেল করে।

### 🗄️ ডেটাবেজ মাইগ্রেশন (বিদ্যমান ডেটাবেজ থাকলে — কোনো ডেটা মোছা/বদলানো হয় না)
**আগে ব্যাকআপ নিন** (Cloudflare ড্যাশবোর্ড → D1 → Export), তারপর ক্রমানুসারে, **প্রতিটি একবার**:
```bash
npm run db:migrate:sellers        # 007 — sellers, সেশন, লগ, products.seller_id; পুরনো সব পণ্য → "NextGenTechBD Official"
npm run db:migrate:orderitems     # 008 — order_items (মাল্টি-সেলার অর্ডার)
npm run db:migrate:subscriptions  # 009 — প্ল্যান, সাবস্ক্রিপশন ইতিহাস, মার্কেটপ্লেস সেটিংস (trial_days = 15)
npm run db:migrate:productfields  # 010 — পণ্যের description ও featured
```
- ⚠️ 007 ও 010-এ `ALTER TABLE ... ADD COLUMN` আছে — **দুইবার চালালে ব্যর্থ হয়**। চালানো হয়েছে কি না দেখতে: `npx wrangler d1 execute nextgentechbd-db --remote --command "SELECT name FROM pragma_table_info('products') WHERE name IN ('seller_id','description')"`
- 008 ও 009 পুরোপুরি repeatable। পুরনো অর্ডারে `order_items` থাকে না (টেক্সট থেকে নির্ভরযোগ্যভাবে বানানো যায় না) — সেগুলো শুধু Super Admin দেখে; নতুন অর্ডার থেকে সেলার-ভিত্তিক ডেটা তৈরি হয়।
- **নতুন ইনস্টল:** শুধু `npm run db:init` + `npm run db:seed` (schema.sql-এ সবকিছু আছে) — মাইগ্রেশন লাগে না।
- **ক্রম গুরুত্বপূর্ণ: আগে মাইগ্রেশন, পরে কোড ডেপ্লয়।** মাইগ্রেশনগুলো শুধু নতুন কলাম/টেবিল **যোগ** করে, তাই পুরনো কোড নতুন স্কিমায় ঠিকমতো চলে (পরীক্ষা করা হয়েছে: দোকান, অর্ডার, ট্র্যাকিং, রিভিউ, অ্যাডমিনের পণ্য/অর্ডার/ড্যাশবোর্ড/কুপন সব ঠিক)। উল্টোটা (আগে ডেপ্লয়, পরে মাইগ্রেশন) করলে মাঝের সময়টুকুতে দোকান ও পুরনো-ধাঁচের অর্ডার চলে, কিন্তু অ্যাডমিনের পণ্য/ড্যাশবোর্ড/রিভিউ/কুপন ট্যাব এবং রিভিউ জমা দেওয়া "no such table/column" এরর দেয়। GitHub থেকে অটো-ডেপ্লয় চালু থাকলে তাই **কোড পুশ করার আগে** মাইগ্রেশন চালান।

### 🚀 মার্কেটপ্লেস ডেপ্লয় চেকলিস্ট
1. Cloudflare Pages Environment variables: `ADMIN_KEY` (লম্বা, এলোমেলো), এবং ছবি আপলোডের জন্য `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET`। D1 বাইন্ডিং `DB` (বিস্তারিত: DEPLOY-GUIDE.md)।
2. ডেটাবেজ ব্যাকআপ → উপরের মাইগ্রেশন ক্রমানুসারে।
3. কোড ডেপ্লয় (`npm run deploy` অথবা GitHub পুশ) — `public/_headers` ও `public/_redirects` সাথে যায়।
4. `/admin/` → লগইন → **🏪 সেলার** → প্রথম সেলার তৈরি → সেলারকে ইউজারনেম/পাসওয়ার্ড দিন (পাসওয়ার্ড তাকে নিরাপদ মাধ্যমে পাঠান, প্রথম লগইনের পর প্রোফাইল ট্যাব থেকে বদলাতে বলুন)।
5. **💳 সাবস্ক্রিপশন** ট্যাবে প্ল্যানের দাম বসিয়ে চালু করুন (শুরুতে দুটো নিষ্ক্রিয় উদাহরণ প্ল্যান থাকে)।
6. ডেপ্লয়ের পর হাতে-কলমে একবার দেখুন: সেলার লগইন → পণ্য যোগ → হোমপেজে আসে → দুই সেলারের পণ্য একসাথে অর্ডার → সেলার নিজের অংশ দেখে → `/store/<slug>` খোলে।

- **অ্যাকাউন্ট তৈরি/লগইন** করতে পারবে — নাম, মোবাইল নম্বর ও পাসওয়ার্ড দিয়ে
- **অর্ডার হিস্টোরি** দেখতে পারবে — লগইন করা থাকলে তার নামে করা সব অর্ডার আইডি, স্ট্যাটাস, মূল্য সহ

**পাসওয়ার্ড ভুলে গেলে:** গ্রাহক `/orders` পেজে "পাসওয়ার্ড ভুলে গেছেন?" চেপে তার মোবাইল নম্বর দিলেই — নম্বরটার সাথে অ্যাকাউন্ট থাকলে সরাসরি "নতুন পাসওয়ার্ড সেট করুন" ধাপে চলে যায়, কোনো অ্যাডমিন সহায়তা বা ইমেইল/এসএমএস/হোয়াটসঅ্যাপ যাচাই লাগে না।

### 🔔 নতুন অর্ডার নোটিফিকেশন কীভাবে কাজ করে

- অ্যাডমিন প্যানেল প্রতি **২০ সেকেন্ডে একবার** নতুন অর্ডার আছে কিনা চেক করে (এটা "পোলিং" পদ্ধতি — সত্যিকারের instant push notification না, কিন্তু ব্যবহারিকভাবে প্রায় তাৎক্ষণিক মনে হবে)
- নতুন অর্ডার পেলে: 🔴 ট্যাবে লাল সংখ্যার ব্যাজ, 🔊 একটা ছোট সাউন্ড, 💬 স্ক্রিনের কোণে একটা টোস্ট মেসেজ (ক্লিক করলে সরাসরি অর্ডার ট্যাবে নিয়ে যাবে), এবং ব্রাউজার ট্যাবের টাইটেলে সংখ্যা দেখাবে
- প্রথমবার লগইন করলে ব্রাউজার **নোটিফিকেশন পারমিশন** চাইবে — "Allow" দিলে প্যানেল অন্য ট্যাবে/মিনিমাইজ করা থাকলেও ডেস্কটপ নোটিফিকেশন পাবেন
- ⚠️ **সীমাবদ্ধতা:** এই নোটিফিকেশন কাজ করতে **অ্যাডমিন প্যানেলটা ব্রাউজারে খোলা থাকতে হবে** (ট্যাব বন্ধ থাকলে/ব্রাউজার বন্ধ থাকলে পাবেন না) — কারণ Cloudflare Pages-এর এই আর্কিটেকচারে সত্যিকারের সার্ভার-পুশ নোটিফিকেশনের জন্য বাড়তি অবকাঠামো (Durable Objects/Web Push সার্ভিস) লাগবে, যা এখানে সেটআপ করা নেই। এর পাশাপাশি প্রতিটা অর্ডারের হোয়াটসঅ্যাপ মেসেজ আগের মতোই সরাসরি আপনার নম্বরে আসে, যেটা প্যানেল বন্ধ থাকলেও কাজ করে

### এই ভার্সনে যা নেই (ইচ্ছাকৃতভাবে বাদ দেওয়া হয়েছে)

- **SMS/ইমেইল নোটিফিকেশন** — এর জন্য Twilio বা কোনো লোকাল SMS গেটওয়ের পেইড অ্যাকাউন্ট লাগবে; সেই সার্ভিসের API কী পেলে যোগ করে দেওয়া যাবে
- **একাধিক অ্যাডমিন/স্টাফ অ্যাকাউন্ট + পারমিশন সিস্টেম** — বর্তমানে একটাই ADMIN_KEY ব্যবহার হয়; মাল্টি-ইউজার সিস্টেম করতে হলে বড় আর্কিটেকচার পরিবর্তন লাগবে
- **কুরিয়ার API ইন্টিগ্রেশন (Pathao/Steadfast ইত্যাদি স্বয়ংক্রিয় ট্র্যাকিং)** — কুরিয়ারের নাম ও ট্র্যাকিং আইডি এখন ম্যানুয়ালি বসাতে হয়; সংশ্লিষ্ট কুরিয়ারের পেইড API অ্যাক্সেস পেলে যোগ করা যাবে
- **2FA / একাধিক সেশন ম্যানেজমেন্ট** — শুধু লগইন লগ আছে, দ্বিতীয় স্তরের ভেরিফিকেশন নেই

## 🚀 লোকালি প্রিভিউ করার নিয়ম

```bash
npm install
npx wrangler d1 execute nextgentechbd-db --local --file=./schema.sql
npx wrangler d1 execute nextgentechbd-db --local --file=./seed.sql
npm run dev
```

তারপর টার্মিনালে দেখানো লোকাল URL (সাধারণত `http://localhost:8788`) ব্রাউজারে খুলুন। লোকাল মোডে D1-এর একটা লোকাল কপি ব্যবহার হয় (আসল ডেটাবেজ প্রভাবিত হয় না), এবং `ADMIN_KEY` টেস্ট করতে `.dev.vars` ফাইলে `ADMIN_KEY=test-key-123` লিখে রাখতে পারেন।
